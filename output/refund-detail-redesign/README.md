# 退款明细 H5 · 优化版

基于用户上传的 `1111.html` 优化，可直接使用独立的 `index.html`，无 CDN、无构建依赖。

## 预览

在本目录执行 `python3 -m http.server 4173`，浏览器打开 http://127.0.0.1:4173/ 。移动端建议通过 HTTP 服务打开。

## 本次调整

- 绿色主色、白色卡片，统一间距、圆角和文字层级；金额使用单独的语义色。
- 居中导航，订单编号单独展示并支持复制，导航右上角提供“退款规则”入口，点击以弹窗展示。
- 展示商品名称、规格、SKU、单价、支付金额和本次退货摘要。
- 未提货/已提货按分组横向展示状态，增加编辑空间。未选中的明细不可编辑。
- 保留全选、清空、数量步进/输入、未提货金额及幸福分自动计算、已提货自定义金额/幸福分、指定商品返还库存。
- 实时汇总金额、幸福分及订单级优惠券；固定底部合计。
- 提交校验金额、幸福分和库存上限，超限时自动展开并定位对应明细。
- 退款确认使用底部浮层，支持取消、Escape、键盘焦点限制；完成页明确演示不会发起真实退款。
- 返回按钮先确认是否重置，防止误丢编辑内容。

## 保留的数据与规则

保留原型演示商品、价格、优惠券、状态分组与数量上限。未提货金额与幸福分依数量计算；已提货可填写 0 件实现仅退款，金额与幸福分单独填写。订单关闭的原始说明保留完整内容，在规则弹窗中展示。原始数据第二个商品的订单数量与本次可退分组数不同，本次沿用分组可退上限，未自行推断业务规则。

这是前端交互原型：无真实退款接口、无登录鉴权、无后端库存变更。生产接入时所有数量、可退资产、上限、优惠券处理、账户权限和订单关闭判断均应由后端返回并再次校验。刷新页面会重置本次编辑。

## 验证

使用 Chromium + Playwright 在 320、390、560、1280px 宽度测试。`verify.cjs` 通过环境变量 `H5_BASE_URL` 指定 HTTP 地址；需要安装 Playwright 和 Chromium，可使用 `CHROME_PATH` 指定浏览器路径。截图保存在 `previews/`，设计比较见 `design-qa.md`。
