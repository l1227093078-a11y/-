# 退款金额统计 PRD

版本：V1.0｜日期：2026-10-21｜范围：移动端退款统计

依据：当前 HTML 原型（含产品经理多选更新，代码版本 `6840a78`）。原型为演示数据；本文补充正式业务的数据权限、异常及验收要求，未表示这些能力已在 HTML 中实现。

## 1. 目标与范围

让已登录用户在账号授权范围内，按时间、商品/分类、市场/门店、产品经理查看退款规模、原因构成、每日趋势及维度分布。

本期包含：首页、四类统计内页、门店下钻、筛选弹层、规则说明、数据权限隔离。不包含退款审批/发起、订单操作、订单级流水页、报表导出及权限管理后台；登录和授权规则复用现有系统。

## 2. 页面与使用流程

登录并校验页面权限 → 首页查看汇总 → 设置筛选 → 查看趋势 → 进入维度明细 → 展开分类或查看门店 → 返回首页。

| 页面/模块 | 内容与操作 |
| --- | --- |
| 首页 | 标题“退款金额统计”；右上角“规则说明”；时间与业务筛选；退款金额汇总；退款趋势；多维度明细 |
| 多维度入口 | 按商品统计、按商品分类统计、按产品经理统计、按市场/门店统计；两列两行，“查看明细”位于各标题下方 |
| 统计内页 | 继承首页已确认的筛选条件，展示分组金额及原因构成；返回后保留首页条件 |
| 筛选弹层 | 商品/分类、市场/门店、产品经理、自定义时间；提供关闭、重置、确定 |
| 规则说明 | 展示第 4 节统计口径及分类、产品经理归属规则；点击“知道了”或遮罩关闭 |

视觉沿用当前原型：浅灰绿背景、白色卡片、绿色主操作；首页无英文副标题，金额汇总卡为白底；趋势标题下不展示“每日退款金额 · 与上方筛选同步”。

## 3. 登录账号与数据权限

### 3.1 权限原则

**有效统计数据 = 登录账号被授权的数据 ∩ 时间范围 ∩ 商品或分类条件 ∩ 门店条件 ∩ 产品经理条件。** 同一维度多选为“或”，不同维度为“且”；商品和分类为互斥筛选模式。

| 场景 | 规则 |
| --- | --- |
| 身份与页面权限 | 未登录进入登录流程；有登录状态但无本页面权限，展示“暂无访问权限”，不请求或返回业务数据 |
| 数据授权来源 | 复用现有账号、角色及数据范围授权；服务端从登录身份解析，客户端不能自行指定他人身份或扩大范围 |
| 数据边界 | 遵循现有主体/组织、市场、门店、商品、产品经理等授权规则；若系统存在租户，先隔离租户。同一账号最终可见范围由现有权限系统确定 |
| 全部与未选择 | “全部商品”“全部门店”“全部产品经理”以及空筛选均指当前账号权限内全部；空筛选不得解除权限限制 |
| 筛选候选与搜索 | 仅返回有权查看的商品、分类、市场、门店及产品经理；关联名称、商品数、门店数和搜索结果同样受权限约束 |
| 父级与全选 | 勾选一级分类或市场，仅选中其下有权限的子项；全选仅选中本账号全部可选项。不得将无权子项计入数量、半选状态或金额 |
| 汇总与下钻 | 首页、趋势、四类明细、分类子项、门店下钻采用相同权限规则；可见父级不能授予访问其全部子项的权限 |
| 接口校验 | 服务端对每次查询及下钻重新校验；篡改商品/门店/经理 ID 或直达内页不能越权。提交无权 ID 时拒绝查询并提示刷新筛选，不静默扩大至全部 |
| 账号/权限变更 | 切换账号清除旧数据与条件；权限收回后下一次查询立即按新权限处理，旧条件失效时清空旧结果并提示重新选择 |
| 缓存与会话 | 缓存按账号有效数据范围、权限版本及筛选条件隔离；登录过期转登录，失败时不得继续显示其他账号或旧权限结果 |

权限示例仅用于验收：若某账号仅获授 A 市场的 2 家门店，则其全选只覆盖这 2 家门店；A 市场汇总也只计算这 2 家，不能看到该市场其他门店数据。产品经理账号是否仅查看本人商品，以现有授权配置为准，不新增默认授权。

### 3.2 无权限与无数据区分

- 无页面权限：显示权限提示，不展示统计页内容。
- 有页面权限但无数据授权：显示“暂无可查看的数据权限”，联系管理员；不展示全平台候选项。
- 有数据授权但筛选无退款：汇总为 ¥0.00、0 笔、各原因占比 0.0%；趋势及内页显示空态。

## 4. 统计口径

| 指标 | 定义 |
| --- | --- |
| 统计时间 | 按退款成功时间归属统计周期，而非下单时间或申请时间；仅计算实际退款成功金额，处理中、失败、关闭不计入 |
| 退款金额合计 | 筛选时间段内实际退还用户的金额合计 = 超时退单金额 + 用户申请退款金额 + 核销后退货退款金额；三类互斥不重叠 |
| ① 超时退单金额 | 订单超时未取货，由门店店员手动超时退单、系统自动退单所产生的退款金额 |
| ② 用户申请退款金额 | 用户未取货之前，主动发起退款申请并退款成功的金额，含未发货仅退款与已发货退货退款中用户主动发起的部分 |
| ③ 核销后退货退款金额 | 商品已完成核销后，由门店主动发起退货退款的金额 |
| 退款记录数 | 当前有效范围内退款成功记录去重数，以退款成功业务单号为唯一键；同订单分次退款按各次成功记录计数，商品分摊不得重复计笔 |
| 原因占比 | 该原因金额 ÷ 当前范围退款总额 × 100%，显示 1 位小数；总额为 0 时为 0.0%，四舍五入可能使占比和略有偏差 |
| 分类归属 | 两级结构：一级分类、二级分类；商品归入二级分类，再汇总至一级，不展示三级 |
| 产品经理归属 | 一个经理可绑定多个商品；按商品归属经理聚合；关系变更按退款发生时归属计算，不用当前绑定关系改写历史 |

计算以分为单位，聚合后格式化；筛选后的同一数据集用于全部模块，不因图表切换、排序、展开或下钻重复计入。跨商品退款需先按退款商品明细分配实际金额，分摊总额必须等于该退款记录实退金额；分摊细则见第 10 节待确认事项。

## 5. 筛选规则

### 5.1 时间

| 选项 | 统计范围 |
| --- | --- |
| 今日 | 业务时区当天 00:00 至当前时间 |
| 昨日 | 昨日完整自然日 |
| 本月 | 本月 1 日 00:00 至当前时间 |
| 上月 | 上月完整自然月 |
| 自定义 | 起止日期均在近 60 个自然日内（含今日），含首尾日期；开始不得晚于结束，支持同一天 |

自定义日期为空、超范围或起止倒置时，不提交，显示错误并定位对应输入项。快捷时间点击即生效；自定义点击“确定”生效。时间切换保留其他已确认筛选。

上线建议：业务时区统一为 Asia/Shanghai，默认本月且不预选业务对象；原型启动为上月并预选演示对象，仅用于展示。上月快捷项按自然月查询，不因自定义近 60 日限制截断。

### 5.2 业务维度

| 维度 | 展示与操作 |
| --- | --- |
| 商品 | 按名称搜索、多选/取消选择；行内展示缩略图、名称、一级/二级分类、售价；提示仅为“已选 N 个商品” |
| 商品分类 | 一级支持选中/取消其全部可选二级；支持半选、展开/收起及单独勾选二级；显示已选数/可选数，提示仅为“已选 N 个二级分类” |
| 商品/分类切换 | 切换时清空另一模式的临时选择；确认后仅当前模式生效；分类首次进入默认展开首个可选一级分类 |
| 市场/门店 | 按市场分组；支持搜索门店、逐店多选、按市场批量选择/取消、全选/取消全选及一键全选；父级显示半选和已选/可选数 |
| 产品经理 | 按姓名搜索、逐项多选/取消、全选/取消全选、一键全选；行内展示姓名、头像、权限内关联商品数；提示仅为“已选 N 位产品经理” |

搜索不清空已选项；市场/门店、产品经理搜索时保留已选项可见，全选作用于账号全部可选对象，不限于当前搜索结果。商品搜索可隐藏不匹配项，但其选择状态保留。

### 5.3 确认与重置

- 打开弹层，复制已生效条件作为临时条件；操作过程不改变首页统计。
- “确定”：应用当前弹层条件并刷新汇总、趋势及后续明细；业务维度未选项表示权限内不限该维度。
- 关闭、点击遮罩或 Esc：放弃本次未确认修改；下次打开恢复已生效条件。
- 弹层“重置”：仅清空当前弹层临时选择和搜索；商品/分类同时清空两种模式；自定义时间恢复近 30 日。仍需确认才生效。
- 首页“重置筛选”：恢复本月、商品模式及各业务维度权限内全部；不改变登录账号权限。
- 首页已选标签按空间折叠为“+N”；完整选项在弹层查看。弹层不罗列已选名称；未选择时不显示“未选择，将查询全部……”等说明。

## 6. 首页功能

### 6.1 退款金额汇总

展示本期退款总额、统计日期、退款记录数、按退款成功时间统计说明；展示三类原因的金额、占比和构成条。总金额与原因金额显示人民币符号、千分位及两位小数；汇总卡白底。

### 6.2 退款趋势

- 按日展示当前筛选范围内数据；日期正序，无退款日期补 0；默认折线，可切换柱状。
- 折线显示合计及三类原因；合计为灰色虚线。柱状按三类金额堆叠，柱高为当日合计。
- 颜色统一：超时退单橙色、用户申请蓝色、核销后退货绿色；纵轴单位为元。
- 日期多时支持触摸左右滑动、桌面拖动或横向滚动；纵轴固定，日期不挤压至无法识别。
- 点击日期附近图表，显示日期、当日合计及三类金额；滑动浏览不触发误选。
- 切换柱状/折线保留浏览位置和选中日期；时间范围改变后重置；支持方向键、Home/End 和 Enter/空格查看数据。

## 7. 多维度明细

所有内页继承同一权限和筛选，按合计金额降序；只展示有退款数据的分组，显示条目数。每项包括名称、辅助信息、退款总额、三类原因金额和构成条。

| 标题 | 分组与辅助信息 | 进一步操作 |
| --- | --- | --- |
| 按商品统计 | 按商品；显示一级/二级分类 | 本期不下钻订单 |
| 按商品分类统计 | 按一级分类分卡，显示有数据的二级分类数；二级展示相同金额项 | 默认展开金额最高的一级；各一级可独立展开/收起 |
| 按产品经理统计 | 按退款发生时经理归属；显示权限内关联商品数 | 本期不下钻商品/订单 |
| 按市场/门店统计 | 按市场分卡，显示当前条件下有退款的可见门店数 | “查看门店明细”进入该市场下门店统计；面包屑可返回全部市场 |

分类与市场使用统一的分组卡片、金额、原因明细、分隔与操作区域。普通列表构成条以当前列表最大总额为长度基准；分组卡片及分类子项按本项金额占比分配。

门店页显示门店名称、所属市场及退款构成；返回先回市场列表，再回首页，不丢失筛选。商品分类的父级合计等于可见子级合计，市场合计等于其权限与筛选范围内门店合计。

金额展示差异：原型首页/趋势保留两位小数、统计内页按元取整；建议上线内页也保留两位小数，避免视觉上对账不一致，待业务确认。所有计算与验收对账均使用未取整金额。

## 8. 状态与非功能要求

| 状态/要求 | 处理 |
| --- | --- |
| 加载中 | 首次或筛选查询展示加载态，避免将旧结果误认为当前条件结果；快速连续查询仅展示最后一次结果 |
| 无退款记录 | 汇总显示 0；趋势提示调整条件；内页显示“当前筛选条件下暂无数据”；有记录但当天为零时趋势正常补零 |
| 搜索无匹配 | 展示“未找到匹配商品/门店/产品经理”；保留原选择，不自动清空或全选 |
| 请求失败 | 显示失败和重试入口，保留筛选；失败不得伪装为 0 元或无数据 |
| 关系缺失 | 历史商品/经理/分类/门店缺失时归入“未归属/历史数据”，不丢失已授权退款金额；不得借此跨越权限 |
| 更新一致性 | 汇总、趋势及明细读取同一统计口径与数据版本；退款成功事件幂等处理，避免重复累计；页面说明更新时间或数据截止时间 |
| 适配与可用性 | 覆盖 320px 及以上手机宽度；金额、按钮不截断；长名称省略，完整名称可访问；弹层列表滚动且底部操作固定可达 |
| 交互可访问性 | 操作有清晰选中/半选状态；不只以颜色表达；支持键盘选择、弹层焦点限制和关闭后焦点返回 |

## 9. 验收要点

| 编号 | 验收标准 |
| --- | --- |
| A01 权限隔离 | 使用不同授权账号，同条件返回各自数据；无权 ID、直达内页、父级全选、搜索和缓存均不能泄露无权数据 |
| A02 权限变更 | 切换账号、收回门店权限或会话失效后，旧账号/旧范围结果不再可见；空筛选不会扩大权限 |
| A03 金额一致 | 三类原因之和等于合计；逐日合计等于首页；四维汇总分别等于首页；父级等于其可见子级合计；精确到分 |
| A04 去重归属 | 重复成功通知不重复统计；部分/分次退款金额及记录数正确；经理绑定变更不改变历史归属 |
| A05 时间边界 | 今日、昨日、月初/月末、跨年、自定义同日和近 60 日边界正确；非法日期不能提交 |
| A06 筛选行为 | 同维度多选取并集，跨维度取交集；产品/分类互斥；确认才生效，关闭放弃修改；重置语义一致 |
| A07 多选与搜索 | 产品经理与门店均支持多选、全选、半选、一键全选；搜索不丢选择；仅展示已选数量 |
| A08 图表 | 柱状与折线金额相同；多日期可左右浏览至首尾，点击可看当日数值，零值日期和单日显示正常 |
| A09 明细与返回 | 四入口及标题准确；分类展开、门店下钻与返回正确；排序正确、筛选保持、分类/市场样式统一 |
| A10 异常与适配 | 无权限、无数据、失败、加载区分；320px 屏幕金额与底部确定按钮可见可操作 |

## 10. 开发前需确认

以下为现有原型未确定的业务配置，确认后补充执行口径，不影响上述权限隔离原则。

1. 权限映射：现有各角色具体授予哪些组织、市场、门店、商品或经理范围；多角色组合及跨维度授权如何合并，沿用哪套权限服务。
2. 金额与记录：优惠、运费、跨商品部分退款及分次退款的金额分摊；数据源退款成功唯一键；历史归属缺失的映射策略。
3. 上线配置：默认本月还是保持原型上月；内页是否统一两位小数；数据更新时效及性能目标。建议默认本月、全部授权范围、全部金额两位小数；业务时区 Asia/Shanghai。
